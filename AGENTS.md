# AGENTS.md

Guidance for agents (and humans) working in this repository.

## What this is

dissectBCL demultiplexes Illumina (novaseq/miseq/nextseq) and Aviti sequencing
runs. It's a Python package (`src/dissectBCL`, `src/wd40`, `src/tools`) with
CLI entry points `dissect`, `wd40`, `email`, `contam` (see `pyproject.toml`).
It integrates with Parkour2 (the LIMS) via a REST API — pulling sample
metadata before demux and pushing run QC stats after.

## Environment

- Create the conda env from `env.yml`, then `pip install .` (or `.[dev]` for
  tests/lint). Versioning is derived from git tags via `setuptools_scm`, so
  `git` must be present in the env and the repo must be a real git checkout
  (not a tarball without `.git`).
- Production installs use `install_dissect.sh`, which creates a
  version-named conda env per release.

## Code quality

- Pre-commit hooks are configured in `.pre-commit-config.yaml`
  (trailing-whitespace, end-of-file-fixer, check-merge-conflict, codespell,
  ruff check/format, zizmor). Install them with `prek install` or
  `pre-commit install` before making changes — see `CONTRIBUTING.md` for
  full details.
- Run `prek run --all-files` (or `pre-commit run --all-files`) and `pytest`
  before opening a PR.

## Commit messages

This repo uses [Conventional Commits](https://www.conventionalcommits.org/)
(`feat:`, `fix:`, `chore:`, `docs:`, etc.). Releases and `CHANGELOG.md` are
generated by `release-please` (see `release-please-config.json`), which
parses commit messages to decide version bumps — non-conventional commit
messages won't be picked up correctly.

## Tests

Tests live in `tests/` (pytest). Fixtures/sample data for demux tests are
under `tests/test_demux/`.
